
Local real-backend tooling: [developer guide](../../docs/backend-staging-development.md). `local-dev.sh` uses a separate private local configuration and only checks the existing schema. It does not apply migrations.

Runtime isolation uses the external operator-created `mlai-staging-api-internal` bridge (`--internal`, `172.28.240.0/24`, bridge name `mlai-stage-api`, IPv6 disabled). API `.10` and check containers `.11` are the only protected source range `.10`–`.19`. Database `.2:5432`, Redis `.3:6379`, membership adapter `.4:3100` are the only new outbound TCP destinations; established proxy replies work. Caddy `.5` and membership adapter retain their original Chat network. API media has its own persistent volume. No worker, public API port, privileged mode or Docker socket is present.

Install the reviewed root-owned `network-policy.py` manually, then `install` adds only its owned chains/anchors and `verify` checks container identities, attachments and rules. Install policy before starting a candidate/API; verify full topology and a controlled raw-connect test before enabling the broader API. Its owner-only policy is never updated from moving branch source. Docker restart can remove anchors: the deployment gate refuses work until verified policy is restored. Before removing owned rules, stop all API/check containers; `remove-owned` affects only the two owned chains. Rollback keeps database/cache/media volumes, restores the previous image/config and edge attachments, and restores the previous manually reviewed policy. Never flush host firewall rules or prune Docker globally.

Provider inventory: direct HTTP/SDK clients exist across domain code. Runtime has no provider credentials or inherited dotenv. Shared magic-link/email-code and job/website/outbox dispatch boundaries explicitly fail unavailable; account creation/reset/provider callbacks are gated. Raw requests/httpx transport errors are translated to503 where uncaught. Network policy is the final enforcement for additional raw clients; unsupported domain workflows may still report their own configuration error. Real email/payment/calendar/Slack are unavailable. Queue support requires a deliberate local adapter; no workers run.

Backend auto-deployer is manually installed at `/etc/mlai-backend-staging-auto-deploy/auto-deploy.py`, with owner-only config/deploy key/known_hosts and state under `/var/lib/mlai-backend-staging-auto-deploy`. Its repository is fixed to MLAI-AUS-Inc/mlai-backend, `refs/heads/staging`, with a distinct read-only deploy key. Timer checks every two minutes. Installation pins source baseline, migration/helper and dependency hashes. Operational/security/schema changes pause at a manual gate; ordinary domain code and `mlai/urls.py` additions deploy automatically.

Both backend and browser controllers lock their own service, then `/var/lock/mlai-staging-deploy.lock`, covering recovery/build/activation/rollback. A peer activation journal or failed recovery prevents new work; an ordinary operator pause does not pause the other service. `pause` persists first then waits for the service lock; `resume`, `status`, `rollback` operate through the installed controller. Keep current/previous images and private configs; no global pruning. Builds receive no runtime secrets; candidate checks use the isolated runtime network and only `migrate --check`. Activation updates only the API with no dependency recreation. Verify TLS200 on both hosts and exact running image before successful state advances. Recovery precedes the free-space gate;5GiB is required only for new builds.

On host restart, reviewed `mlai-staging-network-policy.service` restores owned anchors after Docker. No moving branch controller/network script runs on the host. If policy verification fails, the updater refuses work; restore the reviewed installed helper/topology rather than relaxing it.

The API has Docker restart policy `no`. Its installed `mlai-backend-staging-api.service` starts only after Docker and successful firewall installation, and `start-api.py` verifies the complete installed helper inventory, network identity, effective rule order and peer recovery under the shared lock before starting the pinned current image. A45second readiness timer repairs that same approved image; it never fetches/builds code. This also covers a process exit without permitting Docker to bypass the gate after reboot. Stop both readiness timer and service before intentional API maintenance. Full host reboot remains outside the focused acceptance run; inspect actual restart policy/systemd dependencies and exercise the startup gate directly instead.

Both isolated profiles explicitly disable Tokenmaxer federation and real Apple purchases. Hosted reporter/callback URLs point to api-staging; local reporter/API/relay URLs are loopback. Read-only digital wallet GET is authenticated and returns real seeded balances with available:false; transaction verification/notifications stay unavailable. Client destination guards accept canonical same-origin `/api/` namespaces (including v2); existing relative paths still use v1.
