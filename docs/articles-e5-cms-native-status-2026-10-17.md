# Native status and diagnostics

The shared website status contract can now represent a native CMS first-article goal without Git scope, a fabricated commit or a required merge. `ARTICLES_CMS_STATUS_ENABLED=false` is independent of the existing status/native goal flags and stays off until the paired clients and remaining acceptance gates are ready.

The read path requires the current authenticated founder, selected company, connection generation and native policy. It reads the original held dispatch/run and calls the private owning evidence validators. It does not schedule a retry, wake a goal, debit funds, call a provider, rearm publication or modify its stored goal/proofs. Current source binding and proof refresh are pure projection operations. Scope is rechecked after proof reads; an owner/company change cannot return the old scope.

The four shared states remain working, needs-you, done and stopped. Working requires a recorded schedule and current scope. Done requires the current original native evidence and an owning publication's verified same-origin HTTPS URL. Copied completion flags, parent URLs, expired evidence, missing owning records and changed source cannot claim a live article. Merge is explicitly not required; all other first-article milestones remain required.

Owner review actions require the original manual-review consent plus the actual stage, draft run and revision. Automatic setup cannot acquire a manual review stop from a copied flag. A recorded reconnect action remains distinct from permission to perform more model or provider work. Existing `cmsGoal` responses follow the current evidence projection when this status flag is enabled, including removal of stale/copied public URLs.

Diagnostics expose bounded native proof references, actual observed run/generation, aggregate usage, class attempts and validated B1 causes. Git source SHA fields are null. Provider origins, credential material/references, consent, original request/billing keys, payer and ledger identifiers are omitted. Token-shaped run references are also omitted. The new dynamic diagnostic code site is exactly audited as a validated B1 projection; no registry bytes or failure policy are changed.

Model dry-run reported no changes. Its database execution remains remote-only.
