# Founder recovery policy

All behavior defaults off. The existing scheduled self-heal sweep and website prepare controller share registry decisions; no additional supervisor or database model is introduced. Legacy organizations keep the existing recovery path and receive read-only observations. `manage.py self_heal_report --json [--org ID]` performs no writes. The optional weekly report writes only private `pillar_strategy.self_heal.dry_run` metadata.

Run decisions reserve attempts under organization/config/run locks, and remote actions execute after commit. Evidence-only run receipts use queryset updates so they preserve `updated_at`. Transient backoff is 1, 2, 5, 10, 20, 40 and 60 minutes, then 60; repair attempts stop at 6, source re-pins at 2, strategy attempts at 2 per rung/source and 6 per organization UTC day, and every item has a 48 hour wall. Current-item delivery stops recovery; historical delivery on the original charge independently prevents inappropriate refunds.

Each reserved remote action retains a `self_heal_v1.pending_action` receipt with action, attempt, state and a two-minute lease. A lost response or worker death retransmits the same attempt rather than consuming another failure attempt. This is an additive durable receipt refinement. The CF resume action retains its existing operation-attempt authority. A revoked cohort or executor flag prevents dispatch on the final check. Automated repository actions first reserve a daily PR slot; actual PR URLs reconcile reservations during ingest. Founder clicks remain allowed and are counted.

Website goal recovery runs within the existing prepare lease. It does not update the operation before the controller's original compare-and-set. Replayed failure occurrence IDs cannot advance the goal twice. Source changes and cancellation still use the existing connection authority guard. A fresh hosted rung is chosen only when the hosted service proves readiness; otherwise native progression continues. Exhausted channels save a copy-ready intent and one source-scoped ticket without asking founders to choose a channel.

Channel fallback preserves the original run request, website tuple and billing. An additive authenticated CF resume control converts only remaining delivery steps to content_only. Enable the new default-off CF `CONTENT_FACTORY_SELF_HEAL_ENABLED` executor before backend `ARTICLES_CHANNEL_SWITCH_ENABLED`, and enable policy last. Pending intents are retained until the executor acknowledges them; a channel receipt alone never proves an article was delivered.

Integration extensions: `registry_policy.organization_read_scope` reuses a joined config only for one decision, without changing global cohort reads or mutation authority. The existing PostgreSQL CI lane now selects the new P2 test modules; the test assignment guard rejects new omissions. A 500 organization observe-only decision batch has at most 3 queries and passes the 2 second local gate; this is a local selection/decision measurement, not provider execution latency.

Validation checkpoint: 257 PostgreSQL P2 tests, 143 broader policy/goal/cohort/reconciliation regressions, 17 focused policy tests. Independent review, the final real hosted/channel composition, full production stop-code replay and deployment acceptance remain open until the final integration checkpoint. No production changes were performed.
