The staged revision binds original company/site/run generation, envelope, handoff/review identity and billing; the final fragment/profile/preview; and each owned image's upload/provider identity, source/public hashes, dimensions, MIME and URL. Timestamp-only public re-observations are excluded from that owner revision. The default final-review read independently requires public image observations within 15 minutes. Historical observations can assemble a private staged artifact but do not pass that fresh gate.

When needed, an internal on-demand recheck requeues only the existing acknowledged URLs. It retains each upload allowance and never uploads again. It does no HTTP under database locks and does not start periodic polling while the owner is reading. Refreshing identical image bytes preserves the staged revision and existing owner review identity; content, URL or scope changes still invalidate it.

## Durable private preparation

The scheduler automatically seals completed media sets into private `cms-stage` operations. Reservation is idempotent and excludes already staged handoffs before applying batch limits. A current-stage read reconstructs the expected artifact from the original private payment, source, provider binding and media journal. Rechecksummed worker/owner JSON, boolean version/generation substitutions, forged approval flags and changed source scope cannot substitute another article.

Stage operations are excluded from owner operation detail, latest summaries, the Git journey and generic Git cleanup scheduling. Their receipts state only `artifact_staged`, with no approval or publication proof. Purge erases their payloads across generations. All existing CMS/artifact gates stay off.
