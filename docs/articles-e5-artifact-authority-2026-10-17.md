# E5 / v2 3.2–3.3: private paid CMS artifact reservation

CMS generation uses the existing article selection, editorial admission, Roo charge and dispatch outbox. A trusted CMS controller passes a private typed scope; owner or worker JSON cannot enroll a reservation. The scope is checked again under the organization/connection locks. The private `cms-artifact` operation, original charge and original dispatch outbox share the billing transaction; an admission or charge refusal rolls back the reservation. No CMS key enters the worker request.

The outer `publishing_channel_artifact` envelope remains CMS while the inner content-only renderer produces an artifact without repository authority. The backend vendors the exact canonical validator, schema and fixture from Content Factory commit `979da46e05a63039192806cd60862951f49ff542` (#1066). CI checks all three allowlisted paths at that immutable revision using the existing read-only contract token. Hosted/portable envelopes are structurally defined by the shared contract; this backend currently admits CMS only.

## Fresh authority and callback identity

The original private reservation binds the founder/company, current CMS connection and generation, credential operation reference, exact saved channel choice, original editorial/topic fields, review policy and billing request key. The authenticated `channel_artifact` admission action resolves the original outbox; caller values can only select it. Its receipt contains only the exact envelope, `allowed=true`, permission mode `none` and empty capabilities. It cannot return a provider credential, Git identity or publication capability.

Dispatch retries recheck this reservation after editorial refresh. Before the first worker POST the backend persists a provisional run carrying the exact original request, allowing callbacks to bind a lost-response dispatch without creating a second run. Sparse callbacks retain the envelope and billing history. Content callbacks and polling recheck current scope; worker claims of approval, Git effects, CMS credentials or live proof are refused. Cancellation/disconnect fences the exact nested CMS connection; no empty-repository query can cancel another portable run. Private artifact reservations are excluded from the generic Git operation scheduler, public operation receipts and journey projection; purge erases their payloads.

Resume and artifact preview retain the original paid intent and recheck current authority. CMS approval, publication, paid revisions and image regeneration still require their own original-artifact/attempt/price boundaries. The legacy article editor refuses CMS mutations before billing, comment changes or worker calls; owned historical reads remain available. CMS generation currently requires manual review: an old Git auto-approval or an `auto_publish` preference cannot grant CMS publication approval.

## Rollout and acceptance still required

`ARTICLES_CHANNEL_ARTIFACTS_ENABLED=false` adds an independent backend gate to the existing CMS/channel flags. Keep all flags off until the paired callback, approval, renderer/media mapping and CMS publisher pass disposable WordPress/Ghost connect → capture → generate → review/publish → public verification → disconnect tests. No provider write, real paid generation, account provisioning, deployment or migration is performed by this change.

This is a generation and authority boundary, not a completed CMS publisher or a first-article-live milestone. The next implementation must reserve the exact approved artifact, upload owned media, apply native author/category/tag mapping, use the immutable post recovery contract, verify the public body and canonical URL, and record provider-specific goal proofs without fabricating Git merge/commit evidence. Unknown post-create outcomes must continue read-only reconciliation and cannot trigger a second publication through a fallback.

Validation: meaningful database-free tests cover private-controller enrollment, exact original payment/content/policy identity, revocation, safe service callbacks, original channel retention, canonical charge ordering and rollback intent, and immutable producer parity. The existing CMS connect regression adds actual ORM reservation/outbox rollback and sparse snapshot coverage for disposable remote CI. Exact test/CI results are recorded in the draft PR; local database execution remains disabled.
