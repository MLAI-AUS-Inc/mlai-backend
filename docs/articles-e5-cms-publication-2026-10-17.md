# E5: durable native CMS publication

The default-off pipeline continues exact private CMS approval into one
cms-publish operation, without another owner action or paid generation.
The original binding, credential, policy, source generation, spend/refund state,
staged article and approval are reconstructed from private persisted records.
Neither a copied receipt nor worker JSON can reserve a post.

## Effects and uncertain outcomes

The immutable post intent includes the final reviewed body/title, original
editorial acceptance, original approval and explicit native author/category/tag/
image placement. Its slug includes the operation UUID; no unrelated existing
post is adopted or overwritten. It preserves inline reviewed images without a
duplicate featured image. The Ghost create explicitly requests public visibility
and uses its documented lossless single HTML card.

A read checks the unique slug before create. Read-only CF prerequisites are
resolved before committing the sole POST allowance. That allowance is persisted
before provider HTTP. A timeout, malformed success reply or interrupted worker
retains the same issued journal and can only reconcile with bounded GETs.
Missing results never authorize another create. Exhaustion retains unknown
outcome and fallback_safe=false; a strategy consumer must not publish a second
copy elsewhere while a native write may exist.

Original scope, native policy, original spend/refund state and the current CF
handoff fence provider effects and results. Current provider credentials are
loaded immediately before each authenticated request. Durable leases recover
interrupted workers, and late replies cannot overwrite cancellation or a newer
lease. Expired public-image checks request the existing media recheck, retaining
the original approval, staged revision and upload/post allowances.

## Public proof

A provider acknowledgement is pending work. The publisher re-reads the same
provider ID and requires unchanged ownership marker, exact raw body/title,
native metadata, status and URL. It then performs a credential-free pinned
public fetch, checks the canonical URL and visible-in-source headline/body,
and compares approved copy, headings, links, images and code through the
existing CMS public semantics validator. Public/CDN unavailability retries
within a fixed budget; modified provider or public content never becomes live.

Completion saves the private public observation and a minimized receipt.
Consumers reconstruct original private approval and validate the owned receipt;
fresh proof/media are required by default. Historical status reads are explicit.
This is bounded HTTP/body evidence, not a browser-computed layout/visibility,
SEO acceptance, Git SHA, merge/build proof or completed goal milestone.

The scheduler filters existing reservations before its bounded limit. Frozen
CMS publication never enters Git cleanup. Private intents, HTML and proofs stay
out of owner operation detail, connection summaries and Git journey reads.
Disconnect/purge erases local private payloads and retains provider content.

## Validation and remaining work

All 1,078 no-database website checks pass, including 17 new actual publisher
control-flow cases across WordPress/Ghost and one exact provider-recheck case.
They cover one-create completion, lost/malformed replies, crash recovery,
occupied slugs, aged images, original refunds, source changes, wrong public
content, late workers, CDN waits and private closed receipts. Network, key and
ledger boundaries use synthetic fixtures; no provider was contacted.

The disposable-CI connection regression additionally exercises real ORM
publication reservation/deduplication, persisted allowance before fake HTTP,
the full approval-to-public-proof path, refund denial and purge. Its database
execution is remote-only and pending CI. Model checks and migration dry-run
report no changes; 778 production failure emissions are audited and all 558
test modules are assigned.

All rollout flags remain off. Native first-article goal/status/UI integration,
strategy handoff, paid revision lineage, unpublish and actual WordPress/Ghost
container/browser acceptance remain required. No local database, actual CMS
write, wallet service, paid generation, merge or deployment ran.
