# Original native first-article recovery

Registered transient and repairable generation failures now schedule a private repair of the original native run. The controller records a causal failure once, persists its measured usage, then reserves and delivers a typed recovery on later leases. It retains the original outbox, analytics identity, artifact envelope, payer, spend and held amount. Internal resume never increments `user_action_count` or optimistically changes the local source generation.

`ARTICLES_CMS_GOAL_RECOVERY_ENABLED=false` is independent of native goal enrollment and the existing Git recovery flag. Recovery also requires B1 policy enrollment and goal budgets. Feature pauses preserve the pending native plan and hold. Completed/stopped source reads retain their separate artifact-read purpose; none grants more model or provider work.

The pure recovery contract, schema and example are pinned to Content Factory commit `efca859a1f6781edeb0c286f9286f519f2d0d0b3` (producer draft PR 1070). CI reads those exact private producer bytes with `CONTENT_FACTORY_CONTRACT_READ_TOKEN`. The existing six renderer/handoff pins remain unchanged. The authenticated CF capability GET must confirm protocol support before POST; there is no optimistic legacy Resume request.

Only `CmsGoalDispatch` constructed by server code can select the canonical private control. Public HTTP/MCP data cannot construct it. Every control boundary rechecks the current owner, original native goal lease, original paid run/outbox and unrefunded hold. The POST requires the exact actual generation, state version, registered failure occurrence, fingerprint and artifact digest. Unknown model cost or active time cannot buy an extra attempt. The private plan records an immutable producer receipt; a lost reply discovers that receipt before retransmission, including after a harmless later mirror snapshot.

Under the organization lock, reservation checks every original media/post journal for issued allowances and persists a provider-work barrier. Any issued, uncertain or confirmed original CMS write prevents source repair. New provider allowances stay blocked while the plan is active, while bounded original model work can continue. Only observation of the actual original run at the receipt's new generation can bind the new source and invalidate its dependent proofs. A producer receipt alone cannot reopen the old source for publication.

The controller uses B1's real failure occurrence for repeated-failure policy. Heartbeats/state-version changes do not count as another failure. A genuinely new occurrence with the same fingerprint escalates through the common bounded policy. The native path never fabricates repository access, a Git SHA, merge proof or approval.

The callbacks preserve CF workflow names such as `direct_generate` and `confirmed_topic`. Original native-run lookup and milestone collection now accept those same article workflow names while retaining the exact original request and envelope identity checks.

Validation: 1,220 website tests passed without a database; targeted native recovery/controller/guard tests cover lost replies, stale leases, current owner/payment changes, provider-write fencing, pause/replay and same-failure escalation. The B1 emission audit passed 808 production emissions; CI assignment passed with 570 fully selected modules and no omissions. Model dry-run reported no changes. A synthetic original-ledger/outbox/recovery/publication ORM scenario is prepared for disposable remote CI only; it was AST-checked locally and was not run against a local database.

Rollout remains blocked on both paired PRs and full remote CI. Real worker-loss recovery after a step claim, native revision/unpublish lineage, shared native status/Chat controls, real CMS/browser acceptance, strategy/hosted fallback and the complete nightly zoo remain separate implementation or acceptance work. No customer operation, paid model call, merge, deployment or flag activation was performed.
