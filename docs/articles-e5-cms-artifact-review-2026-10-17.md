## Durable collection and recovery

A private `cms-review` operation is reserved from the original backend CMS artifact intent, current company/owner/credential/policy, exact source run generation and optional expected review revision. Its idempotency identity cannot be supplied by a worker. The scheduler discovers current completed CMS runs and excludes already reserved source generations before applying its limit, so completed collections do not crowd older runs out of the batch. All existing CMS/artifact rollout gates apply; disabled actions are frozen and cannot fall through to Git cleanup.

Each worker reserves a bounded lease and refreshes private source authority outside locks before reading Content Factory. The service read uses the configured HTTPS origin and API key, fixed endpoint, no redirects or automatic retries, bounded identity-encoded JSON and duplicate-key rejection. It returns only the canonical closed handoff. Provider credentials do not enter this read. A second locked private scope/source/generation check and lease comparison fence every stored result. Disconnects, owner/policy changes, new source generations and stale revisions discard collected data. Interrupted workers resume after the lease deadline; unavailable reads use bounded exponential backoff without restarting article generation or billing it again.

The backend independently checks that the inert preview has its headline outside exactly one owned article body, with the same prose, headings, links, image identities, table/list content and exact code whitespace as the native source. The image manifest must match the actual article images. Expired/unsupported editorial receipts, invalid profiles, hidden or active preview markup and changed sources fail closed. The completed receipt says only `artifact_received`; it explicitly records no provider modification, publication verification or approval.

Collected source and envelopes remain in private operations, excluded from public operation detail, latest-operation summaries and the Git journey. Purge erases their payloads across generations. A separate original-dispatch fix retains exact financial metadata while validating the backend-added provisional actor against the original outbox actor; this fixes the full backend CI callback regression without trusting a worker actor.
