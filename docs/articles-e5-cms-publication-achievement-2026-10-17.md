# E5: recorded first publication — 17 October 2026

A completed native first article previously became “needs attention” as soon as
its 15-minute public body proof expired. The completed operation is no longer
claimed by the runner, so polling could never repair that display.

The controller now records a closed private `publication_achievement` only when
the complete native ledger and owning publication validator pass. It preserves
the original body observation, real completion time, exact goal digest and
publication operation ID. Both public milestone subjects must match that
observation and its original approval. The record is a consistency snapshot,
not permission to run a model, publish, retry or adopt another paid source.

Authenticated status rechecks the current owner/site/policy and the owning
private paid source, approval, intent and single-create journal. It validates
the saved observation at its actual original timestamp and the ledger at the
actual completion time. It never rewrites proof dates, performs HTTP, schedules
work or modifies receipts. A later GET-only health recheck may temporarily clear
or replace the publication child's current observation without erasing the
recorded first publication. The snapshot is removed with native planning data
during existing privacy erasure.

Successful historical status says “First article published”, includes the
original `publishedAt`, keeps original evidence dates and returns the verified
provider-bound URL. The checklist describes the completed setup. This does not
claim the site is currently live or establish ongoing site health. Existing
completed operations without this new record keep the stricter fresh-proof
behavior. Current work admission, model/provider budgets and public body
freshness checks remain unchanged.

Validation: eight new cases use the actual mocked native capture, paid source,
media, approval, provider journal and public body validators. They cover expiry,
read-only status, recheck overlap, owner/key/refund changes, absent/forged private
records, different source/generation and unchanged fresh-body requirements. The
full 1,365-test website no-database group passes; all 583 test modules are
assigned, 823 production failure emissions are audited offline and model dry-run
reports no changes. The existing disposable remote ORM flow additionally reads
the recorded publication thirty days later without HTTP or a new debit; its CI
result must be checked on the PR.

This is stacked on the durable setup coordinator. All rollout flags remain off.
Long manual-review waits, stale pre-existing setup policies, reconnect/rebinding,
hosted fallback and real CMS/SEO/nightly acceptance remain release prerequisites.
No local database, paid model, actual CMS request, merge or deployment ran.
