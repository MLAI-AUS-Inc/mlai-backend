# E5: initial CMS owner intake — 18 October 2026

An eligible founder can open one initial CMS form before a website connection
exists. `cmsOnboarding` is read-only metadata scoped to the current company,
organisation, configuration and domain. It is absent unless initial onboarding,
native setup, status, discovery and enrolled goal execution are enabled. Reading
it refreshes actual ownership twice but performs no HTTP, quote, reservation,
credential processing, selection change or scheduling. Existing connections and
legacy repository configurations do not become new initial sites.

Opening the form can inspect the public homepage, record the owner's explicit
WordPress or Ghost preference, and obtain an actual first-article quote. These
steps do not accept a credential or reserve points. An explicit initial
`cms_platform` preference is permitted even when public observation misses the
CMS; it changes the selection, preserves the observed recommendation, and proves
no access or publishing readiness. The existing select-channel route requires
the current owner's eligible initial entry before accepting this field.

The existing combined acceptance records destinations, native defaults consent,
review policy, first-article target, image placement and the actual quoted cost.
It retains one original native setup, paid subject and cumulative budget through
verification, discovery, generation, review and first publication. A zero cost
must be an actual integer quote; unknown prices never become free.

Initial status now includes `cmsInitialRequestId`, the original acceptance UUID,
separately from the current credential submission UUID. An owner can recover an
accepted setup with a GET after losing its response or after a subsequent key
restore changes the current submission. This field grants no execution authority
and reveals no credential. The closed connection-stage descriptor is unchanged.
The current connection, quote, preference and recovery responses use private,
no-store caching.

Validation: 1,492 database-free journey tests pass, including 69 initial intake,
acceptance and publishing-channel tests. Model validation reports no changes.
The real ORM round trip continues to start from a database-default nullable
repository in disposable SQLite/PostgreSQL CI. All rollout switches remain off;
this does not certify live CMS support or a measured nightly success rate.
