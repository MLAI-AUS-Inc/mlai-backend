# E5 native first-article financial subject — 17 October 2026

New native goals use a versioned monetary subject containing their actual site
operation, owner, connection binding and originally accepted mode and price.
The same subject can be projected from the original accepted setup intent
before a publication policy exists. Policy discovery therefore need not change
the original payment identity or request another debit.

This is payment metadata only. It is neither a goal nor provider authority.
Generation continues to require the exact current native policy, original
consent, source, private worker lease, payer and original ledger. Even replacing
a policy with another real current policy does not let an old goal dispatch.

Native goals without the new private format marker retain their exact original
policy-bound payment keys and bindings. Unknown or coerced markers are rejected;
existing receipts and ledgers are never rewritten. Git payment keys and the
canonical Content Factory contracts are unchanged.

Validation: 80 focused no-database tests and 1,269 website no-database tests
passed; 810 production failure emissions audited and all 574 test modules
assigned to CI. Model dry-run reports no changes. Disposable remote CI also
checks the new subject against the actual native goal, synthetic hold and
outbox flow. No local database, actual debit, model job or CMS write was used.

All rollout flags remain off. This prepares the durable setup coordinator;
initial acceptance, its pre-discovery hold, typed setup lease, provider runner,
setup status and owner controls still require integration before rollout.
