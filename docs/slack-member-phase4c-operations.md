# Phase 4c: Members delivery and immutable Slack actors

This source is a feature-off candidate. Members rooms dispatch through a complete current-authority fence; existing Community bot and owner-private paths retain their respective behavior. It introduces no migration, consent version, flag value or production operation. Community member posting and unlinked-member bot fallback remain Phase 5.

## Commands and current authority

A short leased transaction saves the deterministic create client ID before any Slack lookup or membership probe. Initial selection chooses the Chat author's own current Slack grant. Message edits/deletes use the original message link's recorded poster; reaction removal uses the reaction-add poster. A new request may capture current consent and device authority for that exact original stable grant/user/connection/workspace/Slack subject. The original link keeps its original poster evidence; an existing stamped or armed command never rebases to the new consent epoch. The first exact actor, wire request and source/room/audience scope commit before mutation. A timeout, restart, quota deferral or failed delivery retains that command. Retrying never selects a replacement account, falls back to a bot or rebases an old command to a new audience.

Each execution locks the complete sorted joined User cohort, its grants, Slack connections, devices, memberships and identity links before State, Channel, Delivery and exact target links. Current consent/OAuth identity, verified admitted signing device, source mapping, fresh public/non-Connect source, joined membership, current full admitted-key hash and real audience acknowledgement are checked again. No normal single-owner client is called beneath State/Channel. A pinned actor and current admitted signing device are checked under the owner authority locks before token refresh; refresh occurs before those lower locks. The lease is checked after durable budget admission immediately before each SDK request; SDK automatic retries are disabled. The local authority fence remains held through the bounded SDK or adapter operation and settlement.

Chat creates, edits and reaction additions require current AI-sharing permission. Deletes and reaction removals remain eligible cleanup after AI withdrawal, while current device, source, grant and recorded actor requirements still apply. Slack-to-Chat readers require existing public-channel Slack consent and membership; the original Slack author need not have an MLAI account or AI consent. No Members bot fallback exists, including with flags off.

A separate committed network-attempt record distinguishes definitely unsent work from armed or ambiguous work; FAILED or dead-letter status never proves Slack rejected a request. An ambiguous Slack operation receives exact completion read reconciliation under the same current authority and pre/post public source proof. A client ID is an identity hint, not an assumed provider deduplication guarantee. Missing, partial or conflicting read evidence leaves the attempt unresolved and does not authorize another mutation. Delete/remove absence is not inferred from a partial history scan. A minimal accepted channel/timestamp response survives lease expiry through an exact attempt/command evidence-only compare-and-set; it cannot overwrite a newer attempt, lease or result. Conflicts remain separately bounded. AI withdrawal allows this read-only bookkeeping of an already accepted operation, preserving a later separately authorized cleanup; definitely unsent content still cannot post after withdrawal.

API user-token attribution is distinct from the ordinary-client Phase 8 canary shape. A current captured user grant and exact returned Slack user are required. Any supplied application/bot markers must unambiguously bind to the configured user app in both message and response; absent, malformed or conflicting evidence remains uncertain. The legacy classic-only `as_user` option is not added. These are source-level checks, not live attribution proof; a later approved member-post canary remains mandatory. See [Slack chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/) for the current API contract.

The backend rechecks exact public source information before sending. Backend locks serialize local revocation; they cannot atomically serialize external Slack administration after the last source proof or an independent relay administrator during a Slack mutation. An uncertain post-mutation observation is not permission to repeat under a new actor. Live conversion behavior remains a later approved canary requirement.

## Relay admission and imported reactions

A Slack-to-Members command contains an immutable server-generated `member_scope`: exact Chat room, Slack workspace/channel, audience `members`, expected audience generation and hash. The adapter must authenticate that sidecar in the existing kind-27235 NIP-98 event while retaining the exact inner event bytes/ID. The matching Chat release must require scope and atomically validate it under the relay membership lock through event/target mutation. A missing or stale scope cannot be silently upgraded. Backend source alone does not prove that relay capability has deployed.

Imported Slack reactions use the separately reviewed Members virtual-actor policy. Their source identity is distinct from native signing authority. Two Slack authors must remain distinct; a semantic duplicate must return the actual canonical existing reaction event ID. Imported linked display attribution grants no native deletion permission. A later released desktop/mobile candidate and fresh smoke checks for this presentation are required; desktop 0.5.56 and the deferred physical iOS build 95 smoke do not cover the new reaction UI.

## Echoes and dependencies

Public callback, history and repair ingress share exact server-stamp/link echo checks. They bind workspace/channel/actual Slack actor, operation/target/reaction and canonical actual sent-text hash. Ambiguous failed attempts retain their echo identity; completed mutation echoes use a bounded window. Echo candidates additionally need a real armed, ambiguous or acknowledged network attempt matching the immutable command; a merely prepared command is insufficient. Completed mutation candidates are filtered to the one-hour window in the database. Completed edit fingerprints must match the link’s current sent text, so an older edit A cannot hide a manual return to A after B. Reaction evidence must still represent the current unsuperseded effect: a deleted native add link, newer opposite outgoing attempt or later observed opposite Slack callback invalidates the old fingerprint. Strictly newer authenticated reaction observations, including ignored echo receipts, supersede older callbacks at ingress and again under the Channel lock before adapter effects. If a newer add is represented by an existing native reaction, that native effect stays current; the ignored observation is not claimed as a new imported event. An unobserved transition cannot be reconstructed from Slack reaction fingerprints alone; a conservative delayed observation can produce a visible extra external import. New Members Slack reaction links canonicalize approved standard aliases before source identity is persisted, so an add/remove/re-add resolves the exact current imported event even if Slack changes alias spelling. Raw receipts are retained; Community and private identities and existing armed commands are unchanged. Imported source reactions remain distinct and gain no authority to delete native human reactions. An unchanged-text own-post unfurl is ignored. A different manual edit remains distinct from completed obsolete edit fingerprints. A manual mutation indistinguishable from a real unresolved own attempt can still be conservatively classified as an echo; no provider mutation ID is invented to resolve that ambiguity. Exact reconciliation or operator review is required for such cases. A reverse link may resolve a reply parent but never authorizes the bridge to edit or delete a native human Chat event. Such unsupported reverse-origin mutations terminate visibly instead of repeating the dependency loop; a genuinely missing direct create remains parkable and is woken by its later completion.
