# D2 independent source-stop advancement

A source-only wake now retains a private causal fence. The paired stop outbox
must advance before journey/proof reads, because missing old usage or stale
source may otherwise prevent the goal from reaching its article step.
The actual prepare controller now drains this purpose before journey checks.

A separate action=article-source-stop row persists one stop identity and exact
wire request per causal fence. It reuses the original goal/payment; it never
reserves a model or debits points. Each admission and pre/post-HTTP commit
reloads original owner/company/consent, unchanged old request/operation attempt
and actual original spend/refund/payer through canonical billing authority.
A 60-second nonce lease and exact prepare claim prevent concurrent calls and
allow a lost reply to retry the identical request after expiry. No site lock
is held across HTTP. Authentication and bounded private transport are reused.

The purpose returns empty capabilities and permission_mode=none. Generic
validation permanently denies both private source-fence and source-stop
actions, including after flag rollback and for cleanup/cancellation variants.
Later owner revocation cannot commit an observation or turn it into a read
or replacement grant. Ordinary setup/scan replay and sparse legacy controls
keep their existing paths.

The worker receipt is a local control acknowledgement, always quiet=false,
inventory_complete=false and effect_authority=false. The backend continues
to wait for complete reconciliation and records remote_confirmed=false. It
does not yet grant historical artifact reads or a replacement. Next work is
independent token/resource/operation inventory closure, complete accounting,
owned publication/auto-merge reconciliation, a separately admitted historical
read and durable content seal, then current-source execution under the same
original paid root. All rollout flags remain off; draft only.

Reconciliation inherits the original wall, compute, model and class limits.
The first effect-removal pass runs before evaluating those limits; an expired
goal then stops with its original budget reason instead of polling forever.

Validation: 551 combined source-stop/refresh/fence, first-article, lifecycle,
incident, facade/profile and sparse-settings checks pass without DB or network.
The generic-private-action denial regression fails on the preceding backend
revision. All 604 test modules are selected in CI. The read-only model check
reports no changes. Contract, transport and actual synthetic stop examples
are pinned to CF `bdf4bf31fda728839c2dde322c14adc219470187`; the stop
examples are generated by the actual worker control path.

The final remote checks job exposed a Phase A source-work assertion that
prohibited the new ownership lookup. Reproduced the exact test failure, then
allowed only that prepare lookup while still asserting no source-work update.
The full failing website journey/lifecycle CI lane plus the related controls,
source-stop/source-policy and facade/profile lanes now pass 1,807 checks
across 130 modules with database/network access denied. No production
authority or test mutation assertion was relaxed.

## Independent historical editorial sealing

A later prepare pass now advances a distinct action=article-source-history
outbox once the local stop receipt is saved. It inherits the original goal wall
and failure budgets. This purpose preserves content before full external quiet;
it grants no execution. One operation/request is reused for the same stop cause,
current canonical connection/configuration/deletion scope and source SHA. The
original paid key, payer and actual spend/refund are rechecked; no new fee or
paid dispatch is reserved. Current scope comes from the freshly locked connection.

Private service admission reloads the original owner/company/consent/payment,
causal fence, unchanged original request/attempt, exact saved stop receipt and
current goal/source. The response has permission_mode=none, empty capabilities
and the exact history request. Generic operation validation permanently denies
the private history action, including cleanup/cancellation variants after flags
are disabled. A 60-second nonce lease and exact prepare claim CAS guard HTTP and
receipt commits. Lost replies retry the same request; a completed seal is replayed
without repeating HTTP. No connection lock is held during the worker request.

The actual worker captures only an allowlist of original editorial JSON in the
original run's purge ownership. Its response returns hashes and bounded metadata,
never content, credentials, approval or a replacement grant. Stable observed
original/fenced generations come from the real local control memo, including
when backend execution_version was unknown. Usage-only status updates do not
change the saved seal. The receipt fixes quiet=false, effect_authority=false and
approval_carried=false; a source hash returning to its original value still needs
fresh admission for its new current scope. Neither old v1 inspection nor generic
source/cancellation/approval rules are relaxed.

The combined strict database/network-denying check passes 1,665 tests across
123 explicitly selected CI modules. Current history/producer/provenance guards
also pass. All 606 modules are fully assigned in CI and the offline failure audit
validates 868 emissions. The expanded ten-file contract/transport/example lock
pins CF d2cc94a8f755b7deed59a35ce76520aeac2fb5f0; synthetic examples are
generated through the actual worker and reproduce byte-for-byte. Full latest-head
remote CI remains required. No model or migration changes are introduced.

Remaining D2 work is complete task/async-resource/token inventory closure,
uncertain provider and owned publication/auto-merge reconciliation, then separately
admitted current-source execution with the original paid root and distinct
execution idempotency. Fresh build, policy review, merge and live proofs remain
mandatory. All rollout flags stay off and the changes remain draft-only.

## Original website-token broker inventory

New server-enrolled Git first-article workflow operations now create an independent
article-credential-inventory record at operation birth, before dispatch. The
original workflow retains a server-owned marker with the inventory ID and scope
digest. Enrollment requires the existing default-off source-refresh and article
stream flags. Replaying an older operation never retrofits known-zero history.
Original markers remain effective after rollout rollback; a missing/corrupt
channel or a lost marker for a known channel refuses a new mint.

Coverage is explicitly website_token_broker only. The record binds original goal,
workflow operation, connection/repository/source/deletion scope and paid client
key. Each broker call appends a distinct article-credential metadata row before
provider HTTP. Canonical authority guards carry their validated operation only
while locked; nested guards without an operation shadow the outer scope. No
incoming request marker grants enrollment. Admitted attempts keep the original
inventory and accumulated count; each token records its actual attempt/run.

Credential values stay in the existing cache. Durable rows contain only references,
scope metadata, unknown/issued mint state, actual provider expiry, possible-delivery
state and revocation observations. Possible exposure is recorded before returning
a bearer, so a lost reply remains conservative. Missing/invalid expiry is never
delivered for an enrolled broker call. Owner revocation after mint, or metadata/cache
failure, withholds delivery and attempts provider revocation outside locks. Late
metadata settlement does not reauthorize a cancelled run. Neither workflow receipt
updates nor admitted attempt changes can erase an independent credential row.

Revocation discovers retained references from the database as well as cache indexes.
Cache-index loss can still revoke a cached known bearer. Loss of the bearer and
indexes remains pending until its recorded actual expiry or a confirmed revoke.
Unknown mint replies have no invented expiry. Only an observed HTTP 204 confirms
a tracked provider revocation; other outcomes remain uncertain, and a late failure
cannot downgrade a confirmed result. Original-generation credentials can be retired
after reconnect. Each pass limits provider calls to 20, retaining the remainder for
later work. Legacy untracked response handling remains unchanged and never proves
complete coverage. Known channel/credential scope mismatches refuse provider work.

Private records have a metadata state and are permanently denied by generic
operation authority. All private source/inventory actions are also excluded from
the legacy cleanup scheduler, public latest-operation projection and business
pending/overdue metrics. They cannot masquerade as owner tasks or create polling
work. No schema or migration change is required; existing operation envelopes are
used, with separate rows to avoid losing inventory when workflow receipts change.

Validation includes the real canonical authority guard, workflow reservation,
broker and revoker with only ORM/provider boundaries replaced. Two cache-eviction
regressions fail with the preceding revoker. The focused suite passes 22 checks,
including rollback, no retrofit, corruption, lost replies, withheld delivery,
reconnect, scope/context isolation, bounded passes and public projection. Two real
database cases are assigned to disposable remote CI for scheduler isolation and
atomic workflow/channel rollback; no local database or migration was run. The combined strict database/network-denying suite passes 1,695 checks across
125 explicit labels. All 608 modules are assigned in CI; the offline audit checks
869 emissions and the read-only model check reports no changes. Current remote
results are recorded in the PR.

This does not establish complete credential/resource coverage or quiet. Direct
backend verification, deployment and merge token issuers, historical/unregistered
work, deeper operation/task/async-resource inventory and automatic source-stop
reconciliation still need integration. No token state alone proves outstanding
Git/provider mutations have finished. All rollout flags remain off; draft only.


## Goal/source guard and automatic original credential retirement

The trusted local stop also writes a bounded goal/source barrier. It binds the
original connection/generation/repository/deletion epoch, goal and source hash,
with separate original source-scope digests. It covers saved original children
with distinct operation IDs, as well as the captured shared operation. Model
scopes retain detached original goal/source/role metadata; an already entered
scope cannot adopt a later request or operation. Connection rebinding preserves
the goal budget, queue proofs retain a closed goal/source/scope descriptor, and
both eager and queued follow-ups check the fence before entering their body.
Missing original scope proof remains conservative. Barriers survive rollout
rollback, and an exact trusted stop replay restores its durable barrier without
incrementing the original execution generation again.

A different independent goal or later configuration at the same source hash is
not blocked solely by the original source-scope key. Passing this local guard
never grants execution: backend generic validation still denies every workflow
belonging to the fenced goal, including unlisted operations and cleanup or
restoration variants. Current-source work will need a separately admitted role;
changing a hash, operation ID or request is insufficient. Unrelated legacy work
keeps its existing guards. Bounded no-follow reads refuse corrupt, oversized or
symlinked original metadata and barrier files without remote hydration.

After a validated local stop, the actual prepare controller now retires broker
credentials for the exact original operation IDs captured in its source fence.
The first effect-removal pass runs even when the goal compute budget was spent.
Every provider pass rechecks original ownership, payment/refund and stop cause,
uses a private nonce lease and exact prepare claim, and rechecks before saving
control observations. No site lock spans provider HTTP. A pass makes at most two
provider DELETEs per captured operation, four in total. Missing bearers remain
pending but do not starve other known credentials of this call allowance. Lost
replies retry the same original identities; confirmed token observations survive
later owner revocation without granting a new controller receipt or execution.

The retirement record is explicitly scoped to captured_original_operations and
website_token_broker. quiet, inventory_complete and effect_authority remain false.
Goal/source-only credential enumeration would also match later source-hash
reversions, so it cannot authorize retiring a separate execution. Deeper channels
need original source-scope enrollment. Direct backend issuers, complete task and
async-resource coverage, uncertain Git/provider outcomes and owned publication
reconciliation remain outstanding before separately admitted current-source
execution. Original billing and distinct execution idempotency, fresh builds,
policy review, merge and live proofs remain required. All rollout flags stay off.
