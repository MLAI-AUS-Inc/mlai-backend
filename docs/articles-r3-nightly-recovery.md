# Current authority for owned nightly refresh

Only newly admitted `island_refresh` executions with the exact scheduler
principal `{kind: scheduler, service: island_refresh}` and original
`island_refresh_recovery_version: 1` can use this gate. The backend records the
version before the original admission digest and first HTTP dispatch. It does
not add a worker run ID or workflow field into those immutable inputs later.
The existing shared `article` model-dollar/token allowance is frozen at
admission; this service is distinct from paid topic research and never creates
an article debit, founder identity, repository scope or publication permission.

Before control reads and again before issuing a ticket, the gate locks and
rereads the organization, original Run, configuration and current execution.
The original request must remain exact and closed: no source, website,
repository, paid brief or arbitrary fields. Current scope must remain the
original empty organization-only tuple. A missing original version or cap,
changed current ticket/domain, recorded stop, settled execution, frozen or
unavailable retained team pin, offboarding receipt, removed keyword population,
non-seedable configuration, workshop or paused research refuses continuation.

The three-unanswered-delivered-days check uses current existing policy data;
it counts distinct local days and ignores same-day fan-out. The gate does not
pause automations, change configuration, reset source clocks or write policy
metadata. A legacy, unversioned or different service execution cannot obtain
this authority. Existing receipt-based continuation survives disabling new
admission or changing today's budget settings; the original cap remains fixed.

The existing authenticated execution-ticket controller owns original-budget
and complete retained-journal checks, durable claims, current-ticket CAS and
same-key replay. Worker grant preflight must occur outside a CF Run lock, since
that backend controller reads CF budget/history before issuing its ticket.
Actual paired worker recovery is a separate acceptance gate. These changes do
not enable any runtime flag or enroll historical rows.
