# E1 site fingerprint: scope and implementation evidence

Fingerprint capture and consumption have independent default-off flags:
`CONTENT_FACTORY_ARTICLES_SITE_FINGERPRINT_ENABLED` in Content Factory and
`ARTICLES_SITE_FINGERPRINT_ENABLED` here. No migration or customer operation is
part of this change. The owner's continuous implementation request authorizes
implementation and draft review without another design-only stop.

## Stored contract

Content Factory attaches schema version 1 under
`repository_inventory.site_fingerprint`. The existing immutable scan snapshot
stores it. The envelope binds repository, branch, selected app root and exact
source SHA. Each field includes a value, confidence and bounded evidence sources:
framework/adapter/router, app roots, runtime, package manager and lock identities,
build invocation/output, hosting, blog/content surfaces, styling, routing/i18n,
private build input names, sitemap and robots. Unknown values are explicit.

The producer reads allowlisted metadata at the pinned commit without executing
repository programs or a model. Optional public HTTPS observations reject private
or mixed DNS, pin a public address while verifying the original TLS hostname,
decline redirects and bound bytes/time. Persist summaries and input names; no raw
credential values, headers or response bodies. A stable digest excludes capture
time, so repeated observations of the same facts can reuse planning evidence.

The backend rejects changed digests, future versions, malformed scopes and values,
excessive nesting/size, credential keys and mismatched source/repository/root/branch.
Discovery exposes only validated facts. The journey's existing current-source gate
allows B3 to use a confident framework hint. C4 accepts a current same-generation
hosting hint while retaining authenticated provider reads and unknown automation.
A newly captured digest invalidates the corresponding deployment hint cache.
These facts never grant generation, write, merge, deployment or live authority.

## Cross-repository provenance

`contracts/site-fingerprint-v1.example.json` is an example generated by the actual
Content Factory producer and accepted by the real backend validator in tests.
`contracts/site-fingerprint-v1.lock.json` pins its producer commit and exact bytes.
`scripts/check_site_fingerprint_contract.py --remote` checks private source parity
in the existing CI contract step using `CONTENT_FACTORY_CONTRACT_READ_TOKEN`.
Missing read access, mutable refs or mismatches fail closed. No new secret is needed.
Offline validation only confirms local bytes and does not claim remote provenance.

## Validation and remaining rollout work

89 focused tests pass across producer/consumer compatibility, malformed/foreign/stale
facts, strategy selection without publishing authority, and deployment hint/cache
behavior. The Content Factory companion has 124 passing tests across inventory,
metadata/public-network bounds, monorepo cache identity and checkpoint reuse.
The deployment and inventory transport seams are synthetic; no customer site or
production provider was contacted. The draft stack's CI must confirm final heads.

E2 still needs reproducible sandbox build selection and its own lockfile/command
validation. E3–E5 still need native rendering, full-flow fault testing, real nightly
acceptance and delivery channels. This change does not establish universal site
support, a live deployment or the plan's 90% nightly success target.
