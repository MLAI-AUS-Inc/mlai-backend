# E5 preparatory CMS setup authority — 17 October 2026

A private `cms-setup` root resolves one closed original `cms-setup-intent`
record, its actual owner, site binding and credential reference. The typed
`CmsSetupDispatch` identifies only the backend's expiring worker lease. Public
JSON cannot construct that lease or replace the accepted policy choices.

The policy configurator checks that lease before each native defaults GET and
again before committing the actual policy. Cancellation, a different lease,
expiry, changed ownership, connection, credential or configuration fences the
old worker. Provider traffic remains outside database locks. Browser company
selection metadata does not retarget a saved site's background operation.

After a lost acknowledgement, the exact original private policy request can
explain its own single configuration-revision increment. Its replay reads the
actual current saved policy and performs no additional provider GET. Another
real current policy cannot be adopted by that original setup lease.

Transient or unavailable-origin discovery failures produce the existing B1
retryable dependency diagnostic instead of a permanent adapter failure. No
provider objects, accounts, authors, categories or posts are created here.

Setup roots and private intents are excluded from generic Git reconciliation,
public latest-operation summaries, journey actions and operation-detail reads.
The independent `ARTICLES_CMS_SETUP_ENABLED` flag defaults to false. This slice
does not expose an acceptance endpoint, reserve a hold, create a setup root in
production, run discovery automatically or enable rollout; those coordinator
and lifecycle integrations follow.

Validation: 13 new setup-authority cases cover original acknowledgement replay,
both cancellation windows, actual private intent binding, stale public choices,
changed owner/scope, expired leases and retryable provider failures. Related and
full website suites use the no-database runner. Model dry-run and failure/test
assignment audits are recorded with the pull request. No real provider access,
payment, model call, migration or deployment was performed.
