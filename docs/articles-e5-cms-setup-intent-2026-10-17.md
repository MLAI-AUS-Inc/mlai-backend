# Closed original CMS setup choices

A preparatory native setup operation needs to retain the exact price, explicit publication/review choices and original owner/site scope before it contacts the provider. The new private intent contract records that accepted input independently of a native policy, article, goal ledger or worker lease. A missing original policy remains absent. No policy UUID, goal proof or provider default is fabricated to make the record look integrated.

The closed record contains the actual setup operation/request IDs, validated native binding, private credential reference, current public quote, authenticated actor, canonical UTC acceptance time and explicit answers. All three confirmations must be boolean true, including for a legitimate zero price. The accepted cost must equal the displayed current quote, and the quote must match the separately resolved company, connection generation and native platform. The owner can explicitly choose review even when the displayed existing policy used automatic publishing.

The public quote producer now uses the same strict display validator. Private provider fields, invented defaults, future versions, malformed values and unrecognized consent fields cannot enter the quote or accepted record. Constructors and validators return independent copies. Diagnostics use a fixed safe message rather than reflecting unknown fields or provider values.

A digest detects inconsistent stored data; it is not a signature, owner consent by itself, a lease, provider permission or payment authority. The eventual coordinator must re-read the real authenticated owner/site and quote, persist the accepted record in its own operation transaction, and validate the current private lease before provider work. It must never accept a client-supplied record merely because its checksum is valid.

The next coordinator work must reserve the accepted first-article amount during initial acceptance, before slow provider discovery can race another wallet spend. Keep one site operation identity through preparation and the eventual native goal. Its financial subject must cover stable site/owner/accepted choices while actual policy and publication proofs stay separately verified. A lost response must find that original operation/hold rather than create a second goal or ask for a second price decision. No wallet or provider endpoint is added in this contract slice.

Validation: 1,259 database-free website tests pass; 39 focused intent/quote/status cases pass, including 13 new intent cases. Tests cover explicit review, absent policy, confirmed zero, numeric/boolean coercion, scope/actor mismatch, canonical timestamps and IDs, copies, malformed/rechecksummed fields, safe errors and both native platform shapes. B1 audit remains 810 emissions; test assignment covers all 573 modules; model dry-run reports no changes.

This is a private data contract, not an enabled one-shot setup runner. Durable coordination, initial payment/hold handoff, typed work leases, retry/stop/revocation handling and paired setup/reconnect controls remain next. No customer/provider/wallet/model operation, flags enabled, migration, merge or deployment was performed.
