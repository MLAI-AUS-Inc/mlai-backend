# Startup team implementation and review evidence

The existing P2 team design sign-off covers this implementation. Both team flags default off. Domain auto-join has a separate later enablement approval; test-mode flag overrides are not rollout authorization. No new database model or migration is used.

Membership lives in the private `pillar_strategy.startup_team` roster. Writes and permission reads use organization/config row locks. The pinned owner never falls through to another company row. A member gets no persistent company row and cannot use owner-only settings, connections, billing administration, first-article, resume, restart, deny, setup, scaffold or proxy consent. Current publish and startup-billing grants are rechecked independently.

The exact My Startup view/method allowlist binds a ContextVar only for the authenticated user and selected company. Dispatch resets it in finally. Domain functions receive this context only when the normal owned-company lookup raises DoesNotExist; it never changes the active company. Legacy and cloned adapters cannot create that binding.

Integration refinements required by existing code:

- The preview grant is actually minted by POST, although IF22 called it GET. POST is allowed with read permission. A member grant includes signed user/company identity; the public preview proxy rechecks current member read access on every request, including portable previews, so removal revokes a previously minted capability. Owner grants retain their existing behavior.
- ProfileView adds only `teamAvailable: true` when the team flag is on. The client then reads the unscoped CompaniesView list, which appends safe member descriptors. ProfileView remains account-owned and receives no member tenant context.
- The roster keeps a minimal company id/name/domain descriptor so a frozen member can still read after the pinned owner company row is deleted. It is an unsaved read descriptor, never a new ownership row. Offboarding retains article data only when actual members still need read access. Pending requests alone do not prevent normal content purge; only the frozen owner pin survives.
- The domain path vendors the complete official Public Suffix List with its MPL2 header and version/commit/hash manifest under founder_tools/data. It has no request-time network or dependency download. It handles wildcard/exception/private rules and IDNA. Known shared hosting, free mail and ISP domains plus configured suffixes are refused. A typed domain or historical email timestamp is not domain ownership: auto-join also requires current consumed email-code proof for both requester and owner on the verified apex.
- An automatically joined unconfirmed member retains a pending owner-confirmation request. Approval confirms that existing member without duplicating it; decline removes the unconfirmed membership and queues the domain-claim alert.
- pending_request_ids is a read-only notification seam so repeated requests receive distinct per-request keys.

Security coverage is in founder_tools.tests_startup_team. T1 covers opaque references and status-only bodies; T2 owner-only decisions; T3 verified/unexpired/current requests; T4 actual cookie Origin and Bearer sessions plus private responses; T5 the complete facade method matrix, owner-only setup/proxy actions, rights and billing; T6 real mail proofs, offline PSL, denied hosts and unconfirmed restrictions; T7 per-user/org limits; T8 hashed, revocable, expiring five-use fragment invites and token-free logs; T9 immediate membership and preview capability revocation; T10 sanitized member payloads and owner-only recipient asks; T11 pinned owner departure/freeze/purge; T12 concurrent PostgreSQL approval; T13 flags-off compatibility and sticky owner pins; T14 exact scoped contexts, exception cleanup and unchanged active selection.

Local checkpoint: 36 PostgreSQL tests plus 7 offboarding tests passed, no model drift, 819 production emissions audited, and CI assignment has no new omissions. Final combined regression, notification/client composition and independent security review remain required before release. No production changes were made.
