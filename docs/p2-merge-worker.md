# P2 publication worker

`publish_merge_worker.run_merge_sweep` owns every run carrying `merge_policy=backend_worker`, including a stamp inherited from its parent/source. All new behavior defaults off. Its durable claim, backoff, cap and deploy schedule live under backend-owned `result.self_heal_v1.merge_worker`; `merge_v1`, `deploy_v1` and both approval receipts use the contract shapes. Bookkeeping preserves CF's `status` and `updated_at`.

Organization/run locks reserve one claim. Provider reads, token minting, CF verify-head requests and live-site fetches run outside database transactions. The worker reads the current connection and approver again after token minting and performs only GitHub's normal merge endpoint with `sha=<CF head>`. There is no admin/bypass parameter, auto-merge enablement, personal credential or installation-wide token. Ruleset and classic required checks are combined; an empty/unknown set requires passed CF verification on the exact head and schedules verify-head itself. Required reviews ask the owner on GitHub once per pull request.

Ordinary article consent is copied verbatim from the matching P1 receipt. An authenticated current CF review supplies actual findings and `reviewFindingsIdentity`, including the exact review identity plus revision. Missing/stale/unreadable findings never mean zero. Reviewed publication uses its approved body hash and explicit zero claims. Setup/scaffold/proxy consent requires the current owner and exact head. A removed or inactive approver cannot authorize a merge.

The deployment watch uses only `ARTICLES_DEPLOYMENT_WATCH_SWEEP_ENABLED`; it does not read or flip the older deployment-detection gate. Exact-merge-commit production deployments/statuses for Vercel, Netlify and Cloudflare Pages precede the SSRF-pinned live-route check. Polls occur at 1, 2, 5, 10, 20 and 30 minutes, then hourly to 48 hours. At 30 minutes one alert and `DEPLOYMENT_NOT_DETECTED` retain the working state and known plain host name. Installation wakes alter due times only on the current P2 organization/connection generation; they never merge or clear caps/consent.

The recovered package's assigned paths are unchanged. The continuation orchestrator additionally authorized narrow non-fenced integration guards in `vibe_marketing_views._attempt_setup_publish_merge` and `_check_and_merge_publish_pr`, so direct legacy APIs cannot merge stamped runs. `control_article_run` also has a narrow owner approve path for stamped proxy/scaffold receipts, independent of a CF workflow rename. It records consent and returns a compatible queued response without a CF generation or a legacy merge. The original `user_may_use_organization` owner check remains the approval check. Existing unstamped behavior is covered by the original regression suites.

The orchestrator authorized `_run_delivery_mode` to expose content-only delivery after a backend-accepted channel intent has a matching CF `channel_switch_cf_v1` completion acknowledgement and actual saved export evidence. A pending/applied acknowledgement, a mismatched run/key, or intent alone keeps the prior mode. The immutable original website request is retained.

Validation uses a synthetic disposable PostgreSQL database, actual row-lock concurrency, mocked outbound services, unchanged P1 regressions, the failure-contract checker and the schema dry run. No migration files, deployment configuration, production credentials or production data were changed.
